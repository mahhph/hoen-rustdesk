# LAN-01 contract candidate 1

Review gate: Mac must acknowledge before server API integration. Executable wire examples are in `wire-cases.json`; Rust validates them in `src/hoen/lan_contract.rs`, Node in `scripts/test-lan-contract.cjs`. No production API is enabled by adding these types.

## Decisions resolving Mac PR21

- All request JSON is UTF-8, at most 4096 bytes, strict unknown-field rejection. Integers are safe nonnegative JSON integers, maximum 9007199254740991. Response listings are bounded to 256 KiB, consistent with the existing broker. Authenticate separately before parsing/acting; bodies never contain an actor identity.
- Alias: 1–64 printable ASCII bytes, no leading/trailing spaces. Compare using ASCII lowercase. Existing non-ASCII aliases or normalization collisions require explicit resolution before v2 adoption; preserve v1 records and identities meanwhile. No Unicode normalization library is needed for this release.
- Role is `client`, `host`, or `both`. Client-only profile has absent/null endpoint. Host/both registration requires a valid IP-literal endpoint and nonzero port; none is ready until its lease reports listener and capabilities ready. Missing and null optional fields normalize identically.
- First v2 write is explicit adoption. After adoption, v1 registry register/updateAddress writes for that identity return 409 `upgrade_required`; v1 reads remain compatible and use current effective metadata. V1 grants also enforce v2 freshness at issue AND consumption. Unadopted identities keep legacy grant behavior. Rollback to a v1-only process requires an explicit authenticated administrator demotion restoring a verified prior profile; never silently demote on an old client's write.
- New lease request is `{requestId, expectedGeneration}`. Server current generation starts at zero. Acquire inside one transaction with compare-and-swap: only matching generation can increment and replace the current runtime. Persist current requestId, canonical request, and original response. An exact retry for the *current* request returns that response without a new generation or longer expiry; changed reuse returns 409 `sequence_conflict`. Older creation retries fail their generation comparison and cannot resurrect a lease. No unbounded request ledger is needed. Expose generation in authenticated self status. Only a locally supervised new runtime reads the generation and claims a lease; a superseded worker must stop publishing, not reacquire in a loop.
- Server lease creation response: `{leaseId, generation, sequence:0, acceptedAt, expiresAt, endpointRevision}`. UUID lease IDs are random lowercase canonical UUIDs and are redacted in diagnostics. All dates are server-generated UTC RFC3339. Lease ID alone is not authentication. New lease is not ready until the first accepted heartbeat. Create retries do not extend the 60-second expiry.
- Heartbeat is the fixture shape, with leaseId in route and generation in body. Compare against authenticated actor's CURRENT lease ID and generation before sequence comparison. Greater sequence accepts atomically, increments endpointRevision only on endpoint change, sets server lastSeen/expiry. Equal sequence and semantically equal body returns the original accepted response WITHOUT extending expiry. Equal sequence/different body gives 409 `sequence_conflict`; lower gives 409 `sequence_stale`; wrong current lease/generation gives 409 `lease_superseded`. Canonical comparison uses validated typed fields, not raw JSON key order or whitespace. An expired current lease may heartbeat again under the same generation if not replaced/revoked; grants remain blocked until it does.
- Online requires fresh lease AND listenerReady AND capabilityReady AND hosting role. Fresh but not ready is Needs attention; at `now >= expiresAt` it is Offline. No adopted lease is Offline. Never-adopted is Legacy/Unknown. A directory transport error is local Status unavailable.
- HTTP errors: malformed/bounds 400 `invalid_request`, unauthenticated 401, revoked/forbidden 403, missing 404, incompatible capability 409 `unsupported_version`, conflicting writes 409 with the enum reason, throttled 429. No free-form diagnostic text is returned to ordinary clients. Grant stale/disabled errors are `host_offline`/`host_disabled`. No success response contains token or private key.
- Capabilities response: `{schemaVersion:2,registrationVersions:[1,2],presenceVersions:[2],configVersions:[1],heartbeatSeconds:15,leaseSeconds:60,maxRequestBytes:4096}`. A genuine unsupported endpoint (404) permits explicitly displayed legacy mode; TLS/auth/parse errors do not masquerade as unsupported capability.

## Configuration and migration fixture boundary

`config-and-migration.json` freezes public configuration metadata and journal field names. It contains only synthetic references, never credentials or PEM private keys. Secret references are service-owned handles, not caller-controlled filesystem paths. The adapter validates ownership before resolving them. Trust union is either `leaf_pin` with root bundle reference + leaf SHA256 or `application_ca` with bundle reference + bundle SHA256; there is no insecure variant. Schema/revision are independent of API protocol version. The entire prepared revision is committed atomically; the active secret-bearing store remains protected and is not exposed through this fixture/public metadata API.

Migration checkpoint values are inventory, backed_up, prepared, validated, activated, verified, committed, rollback_required, rolled_back. Opaque backup references resolve only inside the installer's protected backup root. Invalid/unknown checkpoint or incompatible schema must stop before mutation. Diagnostic output is an allowlisted projection, never serialized raw enrollment.

These metadata fixtures still require platform adapter validators and failure-injection tests in LAN-03/07. LAN-01 is not complete until Mac reviews wire semantics and both implementations consume the fixtures. No certificate changes, API deployment, or identity changes are performed here.
